## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们的高并发映射表用链式分段锁后仍有效能瓶颈，希望改成开放寻址加 CAS。请从零实现一个无锁开放寻址哈希表。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 基于数组的开放寻址，用 CAS 完成插入，冲突按探测序列寻找空位；2) 支持删除：用墓碑标记避免破坏探测链，需说明为什么不能直接置空；3) 支持扩容：负载因子超过阈值时扩容并迁移，迁移期间读写必须都能正确工作；4) 并发正确性：多线程并发插入不得丢数据，需用总数校验；5) 支持墓碑整理：墓碑比例过高时触发整理，整理期间不得丢数据或读到已删除项；6) 支持键的 null 与自定义哈希函数，并说明哈希质量对探测长度的影响；7) 提供统计：元素数、负载因子、平均探测长度与整理次数；8) 测试覆盖插入查找、删除与墓碑、扩容迁移、并发不丢数据、墓碑整理与统计；`mvn -q verify` 一条命令跑通。
