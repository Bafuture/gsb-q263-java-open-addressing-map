## 实现说明（分支 A）

实现位于 `src/main/java/com/example/gsb/map/LockFreeOpenAddressingMap.java`，
测试位于 `src/test/java/com/example/gsb/map/LockFreeOpenAddressingMapTest.java`。

### 设计要点

- **开放寻址 + CAS**：单数组 + 线性探测，槽位是 `AtomicReferenceArray`，
  插入 / 更新 / 删除全部通过 CAS 完成，无锁。
- **墓碑（tombstone）**：删除时把槽位的值置为 `TOMB` 哨兵、**键保留**。
  为什么不能直接置空？开放寻址的查找以“遇到空槽”为终止条件；
  若把中间槽位置空，因冲突而顺延到它后面的键就再也探测不到，探测链被截断。
  墓碑让查找跳过它继续前进，同键再插入时还能原地“复活”。
- **协作式扩容 / 整理**：负载因子超阈值（默认 0.7）或墓碑比例超阈值（0.4）时，
  创建新表，逐槽位 CAS 冻结为 `PRIME` 哨兵后搬运。任何线程读到 `PRIME`
  都会先帮忙搬运（`helpTransfer`），等旧表整体切换后再重试，
  因此迁移期间读写都正确。删除的键不会被搬进新表，整理即重建。
- **null 键与自定义哈希**：null 键哈希固定为 0；构造函数可传
  `ToIntFunction<? super K>` 自定义哈希。哈希质量直接决定探测长度：
  线性探测的理论平均探测长度约为 ½(1+1/(1-α))（α 为负载因子），
  低熵 / 聚集的哈希会造成一次聚集（primary clustering），
  实际探测长度显著偏离该下界（测试里用常量哈希验证了这一点）。
- **统计**：`stats()` 返回元素数、容量、负载因子、平均探测长度、
  当前墓碑数、整理次数与扩容次数。
